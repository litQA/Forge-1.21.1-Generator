# Changelog

## New Content

- Forge 1.21.1 generator target for MCreator 2026.3 with Forge 52.1.21 metadata and Java 21 projects.
- Private 1.21.1 data pack import for recipes, loot tables, tags, dimensions, features, structures, advancements, damage types, enchantments, and functions.
- Forge registry layer using `DeferredRegister`, `RegistryObject`, `ForgeRegistries`, `ForgeCapabilities`, and `ForgeFlowingFluid`.
- Forge network layer with a `SimpleChannel` envelope, payload context adapter, client registry access helper, and the standard message registration path.
- Forge event integration for mod and game buses across generated element and trigger classes.
- SavedData-backed world and player variables with UUID lookup and client synchronization.
- Forge biome modifiers, global loot modifiers, compostables, dungeon spawn hooks, and villager trade listings.
- Forge client extensions for items, armor, fluid types, and mob effects.
- Forge 1.21.1 build workspace using Gradle 9.9.1 and ForgeGradle 7.

## Changes

- The generator name is `Minecraft Forge for @minecraft (@buildfileversion)` and the build file version is `52.1.21`.
- The generator imports the private `forge-datapack-1.21.1` resource tree and does not register a second generator.
- Generated projects use `mods.toml`, `META-INF`, the Forge 1.21.1 dependency ranges, and the `runClient` / `runServer` tasks.
- Generated projects request Java 21 and write UTF-8 sources.
- Mixin configurations use the isolated `net.mcreator.<modid>.mixin` package, `required=false`, `defaultRequire=0`, and no mandatory refmap.
- The custom biome preset bridge uses reflection instead of a package-private Mixin accessor.

## Fixes

Fixed 29 bugs.

- Forge registry and capability replacements no longer reference NeoForge types.
- Fluid blocks, buckets, and fluid types use Forge 1.21.1 APIs.
- Item, armor, and potion client extensions use `initializeClient` callbacks.
- Attribute modifiers convert custom registry objects to holders without changing vanilla attribute holders.
- Tool, block, and plant experience and durability overrides match Forge 1.21.1 signatures.
- Block entity and entity capabilities are exposed through `getCapability` overrides.
- Block entity persistent data uses a per-level SavedData store.
- Player variables no longer depend on attachment types.
- Network message records implement the generated payload contract and register through the generated channel.
- Sign blocks are added to the vanilla sign block entity type through a reflective field replacement.
- Global loot modifiers and biome modifiers use Forge serializer registries.
- Generated event subscribers register on the Forge event bus that owns their handler methods.
- Custom fluid types register through the fluid-type registry key instead of an uninitialized registry holder.
- Game-bus classes including commands, triggers, overlays, brewing recipes, trades, fuels, boats, and GUI containers no longer register on the mod event bus.
- Generated client run configurations pass MCreator JVM options through the ForgeGradle 7 launcher API.
- Generated workspaces enable ForgeGradle 7 source-set output merging so mod classes and resources are loaded from one mod file.
- Custom network messages set `context.setPacketHandled(true)` after dispatch so Forge does not schedule the same payload a second time on the render thread and consume it twice.
- The generated mod installs a guarded, data-populated `LootModifierManager` fallback when Forge 52.1.21 leaves it uninitialized in the development client; normal servers where Forge initializes the manager are unaffected.
- Custom potion-effect procedure expressions resolve `RegistryObject` effects through `getHolder().orElseThrow()` instead of passing the registry object directly.
- Generated procedure calls are fully qualified and block, block-entity, plant, init, and brewing templates carry the imports needed when a converted workspace does not run a Gradle sync first. The workspace base includes a Forge 52.1.21 import cache for initial code organization.

## Known Limitations

- Forge 1.21.1 does not expose a Boat type extension point. Custom boat items use the vanilla oak boat type and custom boat tick procedures run for boats in the level.
- Forge 1.21.1 does not provide `EffectCure` metadata. Honey cure metadata is omitted.
- Unbreakable tools remove the maximum damage component through a generated `components()` override rather than a component event.
- Forge 1.21.1 lacks the NeoForge global loot modifier `add_table` type. The generator supplies a private `add_table` serializer.
- Critical hit disabling and sweep disabling are not exposed by the Forge 1.21.1 critical hit event. Those event parameter mappings are unavailable.
- Custom raider types use Forge's runtime enum extension through reflection because the vanilla nested enum is package-private.
- Mixin refmaps are not generated by the offline workspace. Mixin configurations are optional and use `defaultRequire=0`.
- The execution sandbox blocks MCreator's integrated ForgeGradle AccessTransformer step through Java's writability check. Direct Gradle compilation and client launch were validated outside that integrated step.
- If Forge's reload event does not initialize `LootModifierManager`, the generated fallback loads global loot data at player login. If that manual load fails, the manager remains empty for the session and logs a warning rather than crashing mob loot.
